# High-utility/high-cost overlap and frozen-fragment cache gate

Date: 2026-09-28. This is a synthesis of existing P15 evidence and a read-only algebra/source feasibility screen; no new GPU run or model edit.

The separate P15-P0 preregistered oracle (`p15_p0_return/artifacts/P15_P0_REPORT.md`) used exact Gaussian–tile intersection counts and a fractional-knapsack upper bound over primitive selections in six room/bicycle cells. At 50% of intersection budget, **0/6** cells retained the predefined minimum viability gradient-energy level. Median top-20% gradient-energy primitives consumed 80.20% of intersections. This is a proxy bound, not a theorem about long-run training or all possible representations, but it is strong evidence against simply freezing/omitting an expensive primitive subset as the main speed path.

For a fixed ordered raster fragment, color/transmittance pairs compose as `(C1,T1)∘(C2,T2)=(C1+T1*C2,T1*T2)`. This suggests caching consecutive frozen fragments per training camera while rerendering live fragments. It does not yet yield a viable method: any parameter or depth-order change invalidates a fragment; active and frozen Gaussians can interleave, so one background image cannot represent all frozen work; per-view fragment storage and refresh must be counted. Freezing high-work states to create reuse would change optimization, and the existing FastGS room 20K→30K trajectory still improved PSNR, SSIM and LPIPS. The P15 overlap makes a high-work/low-utility freeze population especially doubtful. LFH archive/residual training and Flash Cache are close prior work; the composition identity alone cannot establish originality.

**Decision:** no Luna experiment on simple primitive freezing, cached fragments, or another cost-aware subset. The next candidate must change the representation or render-work structure while preserving useful full-resolution updates, and must identify a concrete multiview quality mechanism before a training arm. This is a search constraint, not a claimed solution.
