# HTGS prior-art boundary (2026-09-27)

Primary sources: [Hahlbohm et al., arXiv:2410.08129v2](https://arxiv.org/html/2410.08129v2), especially §3.3 and Tables 1, 3; [official implementation](https://github.com/nerficg-project/HTGS). This is a source review, not a local reproduction.

HTGS already sorts and alpha-blends the frontmost `K` per-pixel fragments, then combines the remaining fragments into an order-independent tail. Its equations (17)–(18) use an alpha-weighted tail color and the product of tail transmittances. The paper explicitly notes that tail derivatives can be precomputed per pixel for an efficient backward pass. Thus a front-core/aggregated-tail proposal, including shared tail backward state, is occupied prior art. It is also an approximation to fully ordered alpha compositing: swapping two fragments changes the ordered emitted color by `T_before * alpha_a * alpha_b * (color_a - color_b)` in general. The tail formulation cannot simply be described as preserving the original renderer exactly.

HTGS also already combines perspective-correct evaluation of volumetric 3D Gaussians with tighter global and per-pixel culling. Its Table 3, for five Mip-NeRF360 outdoor scenes, reports 3DGS at 21m17s / 24.64 PSNR / .730 SSIM / .265 LPIPS versus HTGS *without* per-pixel hybrid transparency at 17m26s / 24.81 / .748 / .230. The authors attribute much of this speed difference to improved culling. This occupies the broad "perspective correction improves quality while culling saves work" direction; it is not an untouched mechanism to relabel.

The default HTGS Table 1 aggregates train faster than 3DGS and improve SSIM/LPIPS but lose PSNR: Mip-NeRF360 18m40s / 27.20 / .814 / .254 for 3DGS versus 10m07s / 27.17 / .822 / .234 for HTGS; Tanks&Temples 20m18s / 25.27 / .866 / .276 versus 8m33s / 24.62 / .866 / .272. The Table 3 perspective-only ablation is not an isolated single-code-line change: §4.2 lists opacity decay, a 3D filter, changed densification/pruning, tile size, and optimized SSIM. The published 4090 times, split and loss have not been locally aligned with our A100 complete-process, original-loss, FastGS-Big/ACE-GS protocol. Mip-NeRF360's 4×/2× input reduction is a dataset evaluation convention; do not infer that HTGS uses a forbidden within-training resolution schedule from this alone.

Decision: reject front-core/order-independent-tail and perspective-correct-plus-culling as standalone original candidates. The official implementation makes HTGS a source-available strong comparator if a distinct mechanism reaches a matched benchmark gate. Do not spend a Luna training arm on an HTGS relabeling.
