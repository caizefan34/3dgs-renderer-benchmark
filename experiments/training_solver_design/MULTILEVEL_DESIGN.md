# 全分辨率目标的两级随机梯度

2026-09-26，研究候选。目标仍是更快训练且更高重建质量，不声称首创或
已超过强方法。控制变量、Horvitz–Thompson 与多层 Monte Carlo 都是已有数学。

## 核心机制

把全分辨率原始 0.8 L1 + 0.2 D-SSIM 按等面积块分成 F_b，构造低分辨率
渲染的块损失 H_b。每次低分辨率完整渲染，只有抽中的高分辨率块及其
SSIM 邻域精确渲染。令 z_b 表示是否抽中、p_b>0 为真实边际纳入概率：

```text
Lhat = mean_b[ z_b/p_b * F_b + beta*(1-z_b/p_b)*H_b ]
E[Lhat | theta, sampling history] = mean_b F_b
```

采样分布和 beta 必须在本次抽样前确定并停止求导；完整 H 与被减去的
H 必须使用同一个定义和当前参数。适当条件下梯度期望也相等。这不是
单纯低分辨率训练，更不是缓存过时梯度后省略其修正项。

稀疏像素提供完整目标的修正；粗层若能预测细层的梯度波动，随机误差
可能下降。若二者弱相关/反相关，beta=1 会增加方差。无偏也不等于 Adam
轨迹相同、无精度损失或更快收敛。要测方向相关性、原始/预条件梯度误差
及同时间质量，不能只证明上式成立。

## 直接先行工作与差异边界

- TurboGS (arXiv:2606.15924) 已有持续误差/年龄图、几何相关视角选择、
  tile 内稀疏像素、稀疏光栅化、误差驱动增密和 moment-damped LM。
  其 §3.7 使用稀疏 L1 + tile NCC。不能把“只训练重要像素”作为新贡献。
- VIRGi (arXiv:2603.02986) 已有多视角 patch 训练（用于重着色系统）。
- Eulerian Gaussian Splatting (arXiv:2605.29136) 已对可学习空间分布采用
  无偏梯度与控制变量；“3DGS 使用控制变量”也不是新颖性主张。
- Flash Cache (arXiv:2409.05867) 已阅读全文中的 §4.1 控制变量与附录证明：
  便宜 radiance cache 加昂贵残差修正用于逆渲染，构成直接相关先行工作。
  更广的多精度可微渲染先行工作仍待审查。

这里仅提出可检验的具体组合：对标准 3DGS 全分辨率 L1+SSIM 梯度使用
当前低分辨率控制变量和带 halo 的细层块修正。当前关键词检索未发现
同名机制不构成新颖性证明。来源快照在 sampling_sources/。

## 实现契约与成本

1. 首版固定 9×15 等面积块；1080×1920 与 2×/4×缩小图均可整除。
2. 每个 SSIM 核 11×11；细层块要渲染周围 5 像素 halo，只在核心计入
   损失。全图外沿沿用原 zero padding。忽略 halo 会改变目标和梯度。
3. 相机内参随代理图尺寸缩放，GT 使用 area 下采样。代理不要求等同
   于细层图像平均，但关联程度与具体 eps2d/抗锯齿行为必须实测。
4. 不改变标准 fine 模型、clamp、loss、增密/SH 语义来制造对照优势。
5. 计算两次投影、排序/交集、完整粗层、稀疏细层及 halo、采样/图更新、
   optimizer 的总成本。像素比例不是时间比例；多视角会增加投影开销。
6. absgrad/增密统计是非线性的，不能因为 photometric 梯度无偏就说
   原增密统计也无偏。完整训练前必须明确其采样校正或独立统计方案。

## 第一个门：真实参数梯度是否有可降低的方差

在现有真实检查点和原三张 A 视角上，先用完整细图作为诊断 oracle，
按随机四分块组得到 1/4 抽样率。四组平均应恢复全图梯度。比较普通
采样与 beta=1 修正的全参数误差，同时记录保存的真实 Adam 动量历史下假想下一步更新
的误差；oracle 最优 beta 只作机会界，不能作为已实现策略。

这个 oracle 故意仍渲染完整细图，所以不提供稀疏实现速度证据。
若方差确有余地，再利用现有 gsplat 稀疏/掩码接口验证 halo 与真实
计算成本，之后才做完整训练对照。不能用无偏代数或微基准代替目标。

## 实测后的设计推进

见 MULTILEVEL_RESULTS.md：原生半尺寸代理的确明显降低梯度噪声，但双路、
共享投影/SH、选区损失以及直接缩放 conic 的原型均未在 garden 超过原生。
目前不进入完整训练或声称取得强优化。

下一项结构性机会是“一次交集排序、两个精度的残差校正”：factor=2 的
fine tile16 与 coarse tile8 覆盖同一连续图像区域，在 scaled 代理定义下
尝试共用深度排序列表。先比较独立列表与共享列表、测出可消除的排序成本；
API 尚不支持 3DGS tile8，须在独立原型支持后验证图像及全部梯度，不能
直接修改冻结运行库。两次 alpha 遍历的成本仍在，收益并未证明。

质量侧真正待证的是：相同墙钟内，较低块采样噪声能否弥补额外粗层成本，
同时保持高频重建与增密行为。每步更便宜、梯度更稳定与最终质量更高是
三个不同验收门；任何一个不能替代另一个。
