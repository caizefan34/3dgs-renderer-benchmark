# 两级残差校正：机制成立，整体训练优势尚未成立

这是固定检查点诊断，不是从头训练或正式未见视角评估。用户目标仍是训练更快、
重建质量更高。当前没有证据支持 SOTA、首创或完整训练 2× 的主张。

## 提出的具体优化

每步完整计算便宜的粗层梯度，再用抽样的精确高分辨率块校正粗层误差：

`g_hat = g_coarse_full + sum_b z_b/p_b * (g_fine_b - g_coarse_b)`。

此处 block 梯度包含全图归一化。粗细层使用当前同一模型；抽样前固定概率和
控制变量系数。对原始全分辨率 0.8 L1 + 0.2 D-SSIM 目标保持条件无偏，
而不是永久丢掉高频细节。11×11 SSIM 必须精确保留 5 像素邻域。

工程实现共享投影与 SH，并只计算被抽中核心的细层损失。机会来自降低
块采样噪声与减少像素工作；额外粗层必须足够便宜，否则机会不能兑现。
无偏不意味着 Adam 轨迹、增密统计或最终重建质量自动保持。

## 原生粗层的真实梯度机会

room/garden 的真实 step-2000 参数与 Adam 历史，原三个 A 视角各自固定。
细图 1920×1080，9×15 等面积块，两个随机四分组种子，每次选一组，
边际纳入概率 1/4。枚举全部组作为梯度 oracle；细图故意完整渲染，不用于测速。
代理用 area GT 下采样、缩放相机内参，eps2d 保持 .3。

宽高各减半、beta=1 时，六张视角各参数组的
`校正估计梯度 MSE / 普通块采样梯度 MSE`：

| 参数 | 最小—最大比值 |
|---|---:|
| 位置 | 0.078—0.196 |
| SH | 0.008—0.037 |
| opacity | 0.009—0.031 |
| scaling | 0.008—0.040 |
| rotation | 0.032—0.125 |

所有组均降低噪声。保存的真实动量下，假想下一步 Adam 更新误差比为
0.379—0.708；这仍不是优化轨迹。四倍缩小代理有多个比值超过 1，不能
认为更粗一定更好。枚举组的平均梯度残差很小，但 GPU 归约并非逐位确定。
oracle 最优 beta 只作机会界，没有用于选择一个可部署算法。

原始结果：room_multilevel_gradients.json、garden_multilevel_gradients.json。

## 实现正确性与保留的失败

最初 masked_renderer.py 在 room 的原生/组件梯度门失败，尚未进入 halo 门。
诊断证实三张图像逐位相同，L1 符号和图像 clamp 边界也相同；只有 SH
梯度明显不同，在相同外部图像伴随梯度下仍然如此。不是 SSIM、halo 或普通
原子加法波动。

原生 fused SH 激活保存 `post_color > 0` 掩码，等价于 ReLU 在零点使用零导数。
原组件 `.clamp_min(0)` 的零点导数为 1。masked_renderer_v2.py 改为 `.relu()`，
保留旧文件与旧执行身份。room 三张视角随后全部通过原来的图像、梯度及 halo 门，
没有放宽阈值。room_component_gradient_diagnostic.json 保存失败定位证据。

shared_proxy_renderer.py 从 fine conic 推导粗层滤波，复用投影与 SH；粗层仅
使用 fine 可见集合，因此是一个新代理，不声称等价于原生粗层。
其协方差变换与导数通过独立双精度矩阵逆检查；无效投影先消毒，避免 NaN。
garden 三张视角的 fine 输出、梯度、所有四组 halo 都通过原门。

patch_loss.py 只提取所选块及其 halo，对外图沿保持 zero padding。garden
三个视角所有组的选区损失和参数梯度均对齐完整细图的加权损失。

## 当前成本

零学习率 Adam 保持参数固定，但仍更新动量；每模式四次 warmup，三轮随机顺序，
每轮十步。包含反传、交集/排序、Python 调用和优化器；预计算掩码、选区 GT、
数据加载不计入步骤，且无增密。这是固定状态微基准，不能称为完整训练速度。

room 的修正双路版本：原生 15.581/17.922/17.519 ms，双路
15.439/16.871/16.099 ms；只得到小幅步骤收益。

garden 在同一场选区损失审计中的 wall ms/step：

| 视角 | 原生 | 普通稀疏 | 独立双路 | 共享投影/SH | 共享+选区损失 |
|---|---:|---:|---:|---:|---:|
| 114 | 18.497 | 15.516 | 29.328 | 26.737 | 26.386 |
| 128 | 19.573 | 16.553 | 25.521 | 22.824 | 22.461 |
| 133 | 18.634 | 15.183 | 23.898 | 21.373 | 20.980 |

共享计算节省约 2.5 ms，选区损失再省约 0.35 ms，但三张仍慢于原生。
这否定当前非线性滤波代理实现的跨场景加速主张，不能用明显降噪来掩盖成本。

## 直接缩放代理的结果与下一项结构机会

scaled_proxy_renderer.py 让 coarse conic=factor²×fine conic，投影位置除以
factor；不再把粗层 eps2d 重新补回 .3，因此又是一个不同的代理。三个 garden
视角的 fine 图像/梯度和 patch-loss 门均通过。共享+选区版本的步骤时间为
25.314/21.282/19.943 ms，同场原生为 18.458/19.565/18.633 ms，仍全部更慢。
这次没有跑该代理的梯度方差 oracle，不继承原生粗层的降噪数值。
scaled_gradient_probe.py、shared_gradient_probe.py 是尚未执行的脚本。

可能进一步减少的是重复交集和排序。factor=2 时 fine 16×16 tile 与 coarse
8×8 tile 对应同一连续图像区域；同尺度映射的投影/conic、相同深度顺序与
fine 可见集合使共享列表成为可检验的机会。需要先验证列表身份及可省成本。
当前锁定的 3DGS raster API 只支持 tile_size={4,16}，不支持 8；不能直接
把 tile_size 改成 8 当作已可用实现。相关源码为 Rasterization.cpp 与
RasterizeToPixels3DGSSerialBatchFwd.cu，未修改。即便列表可共用，两次 alpha
遍历仍存在；只省排序并不保证足够快。

所有本轮 GPU 作业均已结束。没有启动训练或修改冻结基线。

## 新颖性与验收边界

TurboGS 已有重要区域、稀疏像素训练、误差增密；VIRGi 已有多视角 patch；
Eulerian GS 已有控制变量与无偏梯度；Flash Cache 的快速缓存加昂贵残差修正
也是直接相关先行工作。上述数学和笼统组合不能宣称首创。详见
MULTILEVEL_DESIGN.md 与 sampling_sources/ 的原文快照。

推进训练前要同时确认代理的降噪与真实总成本。后续训练必须比较完整质量—时间
曲线、相同初始化/相机序列、独立评估视角和多种子，计入预处理及采样开销。
absgrad 增密的非线性统计需单独验证，不能由 photometric 无偏性推出。
正式竞争还须复现当前强基线，当前没有完成这一验收。
