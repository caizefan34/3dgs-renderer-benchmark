# SAD high-cost causal gate: frozen state and selection

**Decision: stop.** The top 32 Gaussians account for **2,654,114 of 547,515,685 accepted pairs (0.4847558%)** across the eight registered training views, below the preregistered 5% opportunity threshold. No held-out view was rendered or used, no Gaussian was edited, and no training was run.

The diagnostic used the SAD-GS room original-loss 5K checkpoint at iteration 5000, 1600×1066, `mult=0.25`. It sorted the 272 training cameras by `image_name` and counted indices `0, 39, 77, 116, 155, 194, 232, 271` using the author `render_structgs(get_flag=True)` path with an all-one int32 `metric_map`; per-Gaussian `accum_metric_counts` were summed across views. Ranking is by descending total count, with lower Gaussian ID first on ties. The selected camera names and all 32 IDs and counts are in `frozen_state.json`.

The checkpoint PLY SHA256 is `3a088855de73bcd4e123d105812791ab75dd621bd19b0dc6cc89789b4c552894`. The author checkout remained at `029814fb5ed773e4a794cec5115951a64f610ab8` and clean before and after; hashes of the renderer and native counter sources and the PLY are in `source_model_hashes_before.txt` and `source_model_hashes_after.txt`. The PLY hash remained unchanged.

The pre-existing ignored rasterizer binary in the checkout could not load with the available Torch 2.8 environment because it referenced the old C++ string ABI. To keep the author checkout read-only, the same pinned rasterizer sources were copied into this diagnostic directory and built there against Torch 2.8/CUDA 12.8. The copied `forward.cu` and `rasterize_points.cu` hashes match the author source. The isolated build's extension SHA256 is `19decac2f6a9d42fad232586267570d6344b9fce242ba4b26d31bcb6788182a8`; its build log, hash manifest, and binary are included. The loaded code path is still the native author `get_flag` counter; only the ABI-compatible build artifact differs.

The run used EPIC-05 physical GPU3, NVIDIA A100-SXM4-80GB UUID `GPU-431ac351-20f8-bdf7-d798-1c9a3f545b72`. It was idle before the count (4 MiB, 0%) and returned to 4 MiB, 0%, with no compute process after it. Full before/after snapshots are saved in `gpu_state_before.txt` and `gpu_state_after.txt`.

Two startup attempts did not render: the nominal Python environment lacked NumPy, and the available Torch 2.8 environment could not load the checkout's ABI-incompatible prebuilt extension. After the isolated native build, the first eight-view pass completed all counters but failed to serialize Torch's UUID object into JSON; it made no edits and released the GPU. The corrected script converted the UUID to a string and repeated the same eight-view count, which produced the saved JSON. No training or Gaussian edits occurred in any attempt.
