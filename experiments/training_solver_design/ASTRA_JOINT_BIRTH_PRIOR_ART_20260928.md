# Joint native-birth competition: bounded prior-art audit

Date: 2026-09-28. Author: Astra mechanism audit. No GPU experiments were run; Luna's files and frozen P0 protocol were not changed.

## Decision

**NO-GO as a claimed original algorithm in its present form. GO only as the already frozen P0 diagnostic.**

The proposed experiment compares two native parent-to-children replacements through four legal complete-scene states, 00, 10, 01, and 11. Its mixed finite difference is `I = L11 - L10 - L01 + L00`. No exact match to this complete procedure was located in the bounded search below. This is not evidence of priority. The mixed difference is standard factorial/set-function algebra; the surrounding ideas have close published precedents.

In particular, neither overlapping parents, Gaussian interdependence, joint subset optimization, group counterfactual credit, budgeted splitting, nor disjoint spatial pairing can carry a novelty claim. Renaming those components does not change this judgment. P0 can establish whether a specific SAD checkpoint exhibits a useful finite-birth interaction; it cannot establish an original or deployable algorithm.

## What a positive P0 would and would not establish

It would establish that, for the fixed checkpoints/cameras/candidate pool and original loss, some whole native births interact sufficiently that a selected legal assembled state beats the predeclared controls. The assembled-scene check is essential: disjoint parent IDs do not imply disjoint pixels or zero higher-order interactions.

It would not establish generalization, downstream convergence, renderer acceleration, source-code originality, global subset optimality, or that the native split rule caused the observed held-out deficit. One event's oracle improvement is not a training algorithm. A negative result at P0 should kill this candidate rather than be repaired by searching scenes, events or objectives after seeing the result.

## Conditional follow-up opportunity, not an approved replacement candidate

There is a narrow systems opportunity to investigate only after a strong P0: **an exact finite-edit evaluator that shares unchanged ray context across competing whole-family replacements, then constrains selection by measured rendering work**. This is more specific than the four-state score, but its novelty and speed are unverified. It is not currently a GO decision.

The implementation would merge the sorted footprint streams of the actual parent/child alternatives and unchanged scene context. Each legal branch would maintain its own transmittance, contribution acceptance and early termination. Unchanged intervals could reuse compositing transfer summaries when their contributing stream is valid for that branch. Changed pixels would trigger original-loss recomputation including the full SSIM window halo. The evaluator must exactly agree with independent complete renders, including reordering, visibility threshold crossings, and background color. A baseline renderer's accepted list is insufficient when an edit makes formerly hidden primitives visible.

The potential quality path is avoiding demonstrably antagonistic finite births while retaining beneficial native replacements under the unchanged ground-truth objective. The potential cost path is reducing actual accepted Gaussian-pixel contributions and tile-list/sort/backward work, with shared evaluation amortized over future training steps. Lower Gaussian count alone is not sufficient. Rejecting an occluder may increase downstream work; split children may have smaller footprints even when their count rises. Costs must therefore be measured for each assembled result and the full optimization step.

The decisive inequalities are (a) a stable loss advantage over the same-count independent control and relevant iterative-marginal control, and (b) `future saved training time > proposal + exact validation + repair + extra data-structure time`. All SSIM and visibility costs belong in the second side. Four-state algebra, affine alpha-compositing algebra and interval summaries are themselves standard; a paper claim would need an actually useful exact evaluator/selection integration, a broader renderer-prior-art audit, and demonstrated end-to-end savings.

If exact shared evaluation is too costly, an approximation cannot be presented as exact. If P0 fails, this implementation opportunity loses its demonstrated quality motivation. If a prior exact native-edit evaluator is found, the current proposal has no certified alternate mechanism. We should say NO-GO rather than relabel it as a new score, graph or optimizer.

## Search scope and provenance

The bounded audit used arXiv title/abstract API queries for Gaussian splatting with selection, split, overlap, merge/reallocation, MCMC, differentiable topology, masks, counterfactual and co-adaptation terms, followed by reading relevant method sections of versioned HTML. Query responses are saved as `selection.xml`, `merge.xml`, `mcmc.xml`, `topology.xml` and `targeted_*.xml` under `astra_joint_birth_prior_20260928/`. An exact-phrase-oriented query involving split selection/coalition/set function returned no entries; this is not a full-text or exhaustive search.

The directory contains 22 downloaded versioned HTML/TXT pairs, plus API results. `source_manifest.json` records source URLs, SHA256 hashes, byte sizes and parsed version dates. All parsed dates are no later than 2026-09-28. Existing local SAD and SteepGS snapshots were used separately. SteepGS re-download had an SSL failure; PairDropGS HTML returned 404, so PairDropGS is not treated as full-text inspected. Citation lists, patents, dissertations and all source repositories have not been exhaustively audited. The present report is a method-text audit, not a source-level novelty certification.
