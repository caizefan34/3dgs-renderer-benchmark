## Protocol boundary / next gate

The pinned `train.py` sums two per-iteration CUDA-event intervals into `Training time`: render/loss/backward, then densification/optimizer. Scene/camera initialization, structure-tensor preprocessing, saves, offline rendering/evaluation and full process wall are outside that number. Default `lambda_l2=2.0` adds L2 to the original L1+SSIM loss. Before a baseline result can count, verify all native CUDA kernels on a bounded sample, author configuration parity, every effective image and train/test split, and reproduce a labeled author run with its timing boundary. Then separately run an original-loss, complete-process-wall common-protocol arm on the same host as FastGS-Big. Neither run has been started.
