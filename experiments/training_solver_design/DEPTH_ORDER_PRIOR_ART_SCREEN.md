# 深度排序方向的有界先行筛查（2026-09-27）

**裁决：**“为每条射线计算 3D 高斯深度，再在 tile/像素局部修正排序”不能作为本项目的原创核心。以下核查只覆盖四篇指定论文的相关方法段落，不是穷尽检索、源码审计或复现实验。用户要求的是**完整全分辨率训练更快、正式未见视角质量更高**；渲染 FPS 与训练墙钟、视角一致性与重建 PSNR/SSIM/LPIPS 均不能直接互换。

| 工作 | 原文已覆盖的机制 | 与本项目目标的边界 |
| --- | --- | --- |
| [StopThePop](https://arxiv.org/abs/2402.00525), §3.2–3.3 | 对射线 `o+td` 和 3D Gaussian `(μ,Σ)` 用 `t*=dᵀΣ⁻¹(μ−o)/(dᵀΣ⁻¹d)` 求最大密度深度；采用 tile 深度及逐射线寄存器窗口重排。作者报告完整逐像素排序约 100× 代价，分层方案平均渲染代价约 1.04× 原 3DGS。 | 它直接先于“逐射线深度＋局部重排”；作者强调 view consistency，不能把其渲染开销当成 FastGS 完整训练开销。 |
| [2DGS](https://arxiv.org/abs/2403.17888) | 使用有方向的平面 2D Gaussian 和透视正确的 ray–splat 交点。 | 交点深度已是先行机制；平面 primitive 与 3D 体 Gaussian 的最大密度深度不是同一公式。 |
| [TileGS](https://arxiv.org/abs/2609.03613), §3.2–3.4 | tile 内深度分桶和选择性精确修复，保持与**原基线合成顺序**数值接近。作者报告 RTX 4090 端到端帧速比 1.069×、raster kernel 1.44×；文中明确当前仅实现 forward，backward/训练兼容版留待未来。 | “tile 局部深度 bin＋修复”也已覆盖；其修复目标是基线顺序，不能据此声称修正了 3D 高斯逐射线物理排序，更不能据帧速声称训练加速。 |
| [RoofGS](https://arxiv.org/abs/2608.15785), §IV | 用 32-bit 自适应排序键、融合前端、双像素 ILP 与快速指数近似等做渲染优化。作者报告 4K RTX 4090 平均帧速约 10.1×，相对其基线 PSNR −0.028 dB。 | 是必须考虑的强**渲染**参考；当前核查没有训练 backward、Adam、增密和完整训练质量/墙钟证据，且作者结果含小幅画质差。不能与本项目 A100 训练秒数直接拼接。 |

以上四份 HTML 的本地 SHA256、已核查小节和来源范围见 `topology_sources/sources.json`。RoofGS 与 TileGS 的数字均为作者报告，未在本项目复现。arXiv API 以 `Gaussian Splatting` 联合 `color-aware sorting`、`importance-aware sorting`、`sorting error`、`selective sorting` 做过窄关键词检索，没有得到直接命中；**检索无命中不是新颖性证明**。

## 仍可检验的更窄问题

两条颜色分别为 `c_A,c_B`、有效 alpha 为 `a,b` 的相邻 splat，若前景透射率是 `T`，交换次序的 RGB 差**精确**为 `T a b (c_A−c_B)`；后方颜色项抵消。这提示可在训练中只修复“逐射线真实深度与原生顺序相反、且合成差足够大”的冲突。它和按几何深度无差别重排的重点不同，但公式本身是基础 alpha 代数，不构成原创认证。对多个交换、早停、alpha 截断及 SH 颜色变化，单对分数不能直接相加成准确整图收益。

**机会门：**先在作者 FastGS 的真实全分辨率 room/garden 状态、原生 tile 列表和一组训练相机上离线统计：原生顺序与逐射线深度相反的相邻**实际贡献**对、其 `T a b‖c_A−c_B‖` 分布、重排前后原损失及独立内部训练视角变化。若高影响冲突不稀疏，或完整图像收益小于重放噪声/排序成本，就停止；不把数学恒等式或局部像素改进称为最终重建收益。只有离线机会明显，再考虑把检测融合进一次原生遍历，并计入完整训练成本，与 StopThePop 等同协议比较。正式未见场景/种子和全文源码查重是后续硬门。

## 第一轮真实像素筛查：直接逐射线重排未出现质量机会

`fastgs_order_conflict_probe.py` 在作者 FastGS 提交 `44e02a5…`、room@4100 PLY SHA256 `64160970…438cc48f85bc`、GPU 2 上，用四张 1600×1066 **训练图**各固定随机采 256 像素。数据来自作者 CUDA 的原生 tile 列表和投影颜色/alpha；使用原模型 3D covariance 对每条像素射线计算 StopThePop 式最大密度深度。在**固定原生已接受贡献集合**上重排并重新合成 RGB，与 GT 比较采样像素 L1。排除原渲染器提前停止的射线，因为重排后可能露出原列表后部未读贡献，固定集合不再充分。未提前停止的 425 个像素与作者原图像逐像素重放全部在 `1e-4` 容差内，parity 失败为 0；这不是重排图像的原生 CUDA parity。

合计 425/1024 像素可用，**599/1024 因提前停止排除**；按可用像素加权，重排后采样 L1 平均**变差 +0.0005836**，只有 179/425 像素改善。各视角相邻逆序对的风险总和中，最高 10% 对占约 78.7%–82.4%；这说明颜色/alpha 影响分布集中，**并不说明按风险修复会改善 GT**。重排后的最大单像素 RGB 变化为 0.024–0.034。原始逐相机汇总在 `fastgs_order_conflict_result.json`；探针 SHA256 `b06ac864…2086be3e01d1`，结果 SHA256 `e28abe48…acdd2c9`。

**裁决：**当前“把原生贡献按逐射线最大密度深度直接重排”的版本不值得进入训练 CUDA 或 30K。模型原本就是按旧顺序训练的，固定状态下重排变差**不能证明**从头使用新顺序训练也会变差。该诊断只覆盖一个已开发 room 状态、四张训练图、稀疏像素和未提前停止射线；它没有测完整原损失、SSIM/LPIPS、反向传播、wall-clock 或正式新视角。不能据它断言所有颜色感知/逐射线排序方法无效，也不能因少量像素变好或风险集中而声称原创双赢。若重开这条线，必须先有与直接重排**不同的机制**和能覆盖提前停止射线的完整图像机会证据。
