# 2026 强方法与不同机制的有界先行筛查

2026-09-27。目标仍是**原有效分辨率/原损失下，完整训练更快且正式未见视角 PSNR、SSIM、LPIPS 更高，并与最新强方法同协议比较**。本页是来源核查和一个局部机会试验，不是已证明的原创方法或 SOTA。四篇本地 HTML 的 SHA256 与核查范围在 `topology_sources/sources.json`；所有论文数字均为作者报告，未在本项目复现。

| 工作 | 已核查的关键机制/作者结果 | 对新方案的约束 |
| --- | --- | --- |
| [ACE-GS](https://arxiv.org/abs/2606.21244), 2026 | 当前梯度与动量的余弦一致性决定增密；opacity 梯度敏感度决定在线稀疏化；FFT 高频残差回注属性。作者 Table 1 报 Mip-NeRF 360 平均 5m30s、PSNR 28.10、SSIM .821、LPIPS .215，RTX 4090，称对 Speedy-Splat 更快且更好。 | “动量一致增密＋敏感度剪枝＋频率补偿”不能作为本项目原创核心。其表未列 FastGS-Big/Faster-GS，且 GPU、分辨率/代码/训练边界不同；不能把其分钟与本项目 A100 数字直接排序。核查的 HTML 没有实现仓库链接，完整复现尚缺。 |
| [Volumetrically Consistent 3D Gaussian Rasterization](https://arxiv.org/abs/2412.03378), 2024/2025 | 在 rasterizer 内解析积分 3D Gaussian 沿射线的透射率，改善不透明表面和作者报告的 SSIM/LPIPS。附录 F 同作者环境的 Mip-NeRF 360 30K 时间 3DGS 51.5min、该法 61min；Tanks & Temples 20.5min、33.2min。 | “解析射线积分＋物理 alpha”已是先行，单独使用还未给出完整训练加速。更快的积分实现可能有工程空间，但必须和当前强训练系统比较。 |
| [3DGART](https://arxiv.org/abs/2608.17298), 2026 | 射线追踪下把像素中心反向传播改为 tile–primitive 中心聚合，每个 primitive 在 tile 内遍历像素并归约，降低原子争用。作者 §5.2 对自己的逐像素 ray-tracing baseline 在 1M/2M primitive 分别报告约 3.51×/3.1× 原始训练速度。 | “primitive-major backward 减原子”已经公开。其分母是 ray-tracing pixel-major，不是 FastGS/ACE-GS；不能据此声称赢 raster 训练。 |
| [GRay](https://arxiv.org/abs/2606.30869), 2026 | 利用许多小 Gaussian 对 BVH ray traversal 的扩展性；作者称约 10× 快于 3DGRT 优化、速度接近 raster 3DGS，但画质稍低。15K 对 30K 消融中 LPIPS 略好、PSNR 略差。 | “密集小点＋快速 ray tracing/减半步数”也不是无先行的双赢主张；作者自己仍报告质量取舍。 |

从这些原文出发，简单把 FastGS 换成解析体 alpha、射线追踪、primitive-major backward、动量增密或高频残差补偿，都不是新的核心机制。ACE-GS 作者的 5m30s/28.10dB 与 FastGS-Big 论文的 3.58min/27.93dB **不同协议不可比较**。真正的强方法必须有可复现的共同数据身份、有效输入分辨率、GPU、墙钟边界、评测实现与多场景多种子指标。

**2026-09-27 补查：方向性 opacity 也有直接先行。** [Augmented Radiance Field](https://arxiv.org/html/2602.19916v1) §3.1 式(1)已令高斯 opacity 随观察方向与可学习中心方向的夹角变化，并用角宽 `T`、尖锐度 `β` 控制透明 lobe；角度偏离时 opacity 趋零。它把这种核用于镜面反射及已有3DGS的后增强，不提供本项目的 FastGS/ACE-GS 同协议完整训练加速结论，但“只让高斯在部分视角贡献，以修复外观并避免其他视角干扰”不能直接宣称原创。原文快照 `topology_sources/augmented_radiance_field_2602_19916v1.html`，SHA256 `f6ce43ea8593edd5cb3cb732fb2b081522cd86eac6bf24813679ddefac18c7b`。基于此不启动方向性 opacity 的新实验；未知的跨视角重复表示也未被该先行或当前共享ID代理证明。

## 空间共享几何自由度的真实机会筛查

作为与上述单点动量、射线积分及排序不同的候选，考虑固定局部 Gaussian 组的共同平移 `u_g` 与零均值个体残差 `v_i`，位置写为 `x_i=x_i^0+u_g+v_i−mean_g(v)`。对当前全分辨率损失，组平移梯度为组内位置梯度之和；若多视角、同局部的梯度稳定同向，少量共享几何自由度可能加快几何调整而不用低分辨率图像或额外渲染。此时仍须与**同预算原生 Adam 和放大学习率的 Adam** 比较，且额外分组、状态和终点训练时间可能抵消收益。局部刚性/分组优化的更广先行工作尚未穷尽；这个参数化不是原创认证。

`fastgs_group_motion_screen.py` 在作者 FastGS room@4100 PLY、四张 1600×1066 训练视角 [0,17,54,121] 上，逐图执行原 `0.8 L1+0.2(1−fusedSSIM)` 前反传，只读取 `_xyz` 梯度；未修改参数、优化器或 renderer。用 Gaussian 中心 1%–99% 坐标范围建立每轴 16/32/64 个 voxel；仅统计至少 8 个当前非零总梯度点、至少三视角有组梯度的 voxel。组内梯度一致性定义为 `||Σ_i g_i||/Σ_i||g_i||`，跨视角一致性是组梯度两两余弦平均。阈值 0.5/0.7/0.9 是诊断刻度，不是预先证明的最佳训练规则。

| 每轴 voxel 数 | 合格 voxel/点 | 组内一致性中位 | 跨视角余弦中位 | 一致性≥0.7且跨视角均值正的组所占合格梯度范数 |
| ---: | ---: | ---: | ---: | ---: |
| 16 | 86 / 170,579 | .176 | +.006 | 0.014% |
| 32 | 243 / 127,685 | .222 | −.035 | 1.13% |

四视角逐图 `_xyz` 梯度非零点为 171K–202K。这里的“梯度范数占比”分母**只含合格 voxel 的点**，不是全场景梯度；所有结论仅是此 room 固定状态/这四个训练视角的粗 voxel 统计。结果文件 `fastgs_group_motion_result.json`、探针 SHA256 `9690057e…406553ae7`、结果 SHA256 `43134882…8ba73b5eca8`；模型 PLY SHA256 `64160970…438cc48f85bc`。过程正常退出，完整 JSON 可重算表格。

**阶段裁决：**粗空间 voxel 的共享平移没有足够广泛、跨视角稳定的梯度机会，不进入 FastGS 生产优化器或 30K。它没有测试法向/可见性条件分组、其他训练阶段/场景或真正的共享残差参数化，也不能证明所有群组几何更新无效。若重新开启，先找到显著更大的真实多视角一致梯度覆盖，并在匹配短程原生 Adam、放大学习率 Adam 对照中取得超过重放噪声的完整图像收益，再计入分组成本。当前仍没有满足用户双赢目标的新方法。

## ACE-GS 表格与协议补查（2026-09-27）

对本地保存的 [ACE-GS arXiv v1](https://arxiv.org/html/2606.21244v1) §5–6、表1–3重读；HTML SHA256 `8b930ed65e89b5905b0a2cd1bdb17056d83c9369ca570de81913ed14a1c445cd`。作者说明单张 RTX 4090 24GB、原始图像分辨率、其余超参数遵循原3DGS，并把训练时间定义为从初始化到最终收敛的总墙钟；多阶段基线将预训练和后续细化时间相加。这是作者自述的时间边界，缺少可核对的实现和逐阶段日志，不能等同于本项目 FastGS-Big A100 完整进程墙钟。表1没有 FastGS-Big：ACE-GS 在 Mip-NeRF 360、Tanks & Temples、Deep Blending 的作者均值依次为 5m30s / 28.10 / .821 / .215、3m01s / 24.63 / .860 / .171、3m00s / 30.33 / .912 / .237（时间 / PSNR / SSIM / LPIPS）。

表2只在 Bicycle 单场景做模块消融；完整 ACE 为 5m44s / 25.47 / .753 / .243。去掉在线稀疏 C 为 5m52s / 25.24 / **.757** / .245：完整方法的 PSNR、LPIPS、时间更好，但 SSIM 更低。去掉动量增密 E 为 10m04s / 25.19 / .750 / **.242**：完整方法的 PSNR、SSIM、时间更好，但 LPIPS 稍差。去掉频率补偿 A 为 5m36s / 25.08 / .743 / .246：完整方法三项质量更好，但时间慢8秒。因此表2支持混合目标取舍，不支持“每个模块在每项指标上都严格改善”的断言；单场景消融也不能证明多场景三指标改善的因果归因。作者表3承认其点数/模型存储高于极致压缩方法，例如 Mip-NeRF 360 ACE 为 1.172M / 277.13MB，Speedy-Splat 为 .296M / 70.09MB。直接再做量化/剪枝不是新核心。没有据此启动 GPU 实验。
