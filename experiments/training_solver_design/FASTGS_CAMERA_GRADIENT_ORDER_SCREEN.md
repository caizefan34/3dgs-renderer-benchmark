# FastGS 全分辨率相机梯度顺序机会门

2026-09-27。前半部分记录固定模型状态下的相机梯度几何；后半部分补充同房间的完整续训裁决。用户目标是完整训练更快且重建更好，半分辨率主训练加偶尔全分辨率侦察不符合当前主线。

## 协议

在作者 FastGS 提交 `44e02a5c1d5e9ed64d2ecd4af1cbba14ac92150f` 的 room 第 4100 步模型上，逐张运行 272 张训练相机，实际分辨率 1600×1066，损失为原协议的 `0.8 L1 + 0.2 (1 - fused SSIM)`，`mult=0.5`。每张图提取全部 651,547 个高斯的三维位置梯度，形成 272×272 的 Gram 矩阵。PLY SHA256 为 `64160970e5ea580aea4f79278a8fbe334d8d81ef6e304a903626843cc48f85bc`；Gram 文件 SHA256 为 `7b08f035bf067ad08d6155733c341f4672a1e983dfa2e4450903de3d61d25c9c`。Gram 对角与 FP64 梯度平方和的最大相对差为 `8.26e-6`。

复现脚本：`fastgs_camera_gradient_order_screen.py`。原始输出：`fastgs_camera_gradient_order_result.json` 和 `fastgs_camera_xyz_gram.npz`。GPU 为 EPIC-05 的 A100 第 3 卡。作者源码没有修改。

## 结果与解释

对单次 iid、带逆概率权重的相机梯度估计，按图像损失构造的半均匀混合采样，其**位置梯度**方差为均匀采样的 `0.9709`；按真实位置梯度范数构造的半混合采样为 `0.9231`；需要先知道全部范数的理论最优概率也仅为 `0.9046`。因此，简单的损失加权相机采样没有明显的大幅方差机会。这个计算只覆盖位置参数，且作者实际采用每轮无放回抽样，不能当作真实训练速度预测。

固定梯度下，100 个随机相机排列的最大中心化前缀梯度范数中位数为 `0.2409`；知道全部 272 个梯度后事后贪心平衡的值为 `0.1296`，比例 `0.5379`。这表明**静态 oracle 顺序**能降低这个代理指标，但它需要先计算整轮全分辨率梯度，且模型一旦更新梯度就会变化。没有测量在线维护成本、原生 Adam 训练收益或未见视角质量，也未审查相关先行工作。

**裁决：**损失重要性采样路线暂不进入生产实现。静态排序只保留为待验证研究线索；若要继续，先设计无需额外整轮反向的在线顺序代理，做不同训练阶段和新场景的稳定性/先行工作检查，再把调度成本纳入配对续训。任何完整训练加速或质量改善都必须用相同全分辨率、相同原损失、同协议强基线和正式未见视角证明。

## 后续：梯度摘要与跨阶段转移

使用已存 Gram 的谱分解构造与原位置梯度等价的高斯随机投影，16个种子/维度。按投影后的梯度贪心排序，**再用完整 Gram** 计算真实最大中心化前缀范数。4100步随机排列中位数为0.2409，完整梯度 oracle 为0.1296；8/32/64/128/256/512维摘要的中位数依次为0.3695/0.3103/0.2556/0.2164/0.1781/0.1615。小于128维的简单随机投影甚至没有稳定超过随机排列。此为离线投影仿真，未实现在线摘要或测量其成本。脚本和原始数据为 `fastgs_camera_order_sketch_screen.py`、`fastgs_camera_order_sketch_result.json`。

在同一 room 的 5000、10000、30000 步另外逐张求 272 相机原分辨率原损失的位置梯度 Gram，PLY SHA256 分别为 `bda0a1987247e52a7c965d031473f8bd2b4163d5441d6b72bc9617bb0fbbb69f`、`4927b6a3a2e8fcf8919ffba5f228ac810df1e16f890303b6620314dd8d3ac0ab`、`c2afc615fd244d561bd790e7d7721af1b7a7515222bd5385650e7b886c58516a`。4100步的完整梯度 oracle 顺序转移到这些固定状态后，最大前缀范数为0.1306/0.1274/0.1457，分别是对应随机排列中位数的0.533/0.595/0.846倍。静态顺序的代理效果在同场景仍有一定保持，但不证明真实 Adam 训练效果。数据：`fastgs_camera_order_transfer_screen.py`、`fastgs_camera_order_transfer_result.json` 与各阶段 Gram/结果文件。

## 后续：低成本相机位姿顺序的完整续训裁决

仅用训练相机的位置和旋转矩阵定义核 `K_ij=exp[-(d_pos(i,j)+d_rot(i,j))/(2×0.5²)]`，两种平方距离各按所有训练相机对的中位数归一化；在中心化核上贪心平衡，得到每轮无放回固定顺序。`1:1` 权重、带宽`0.5`是在 room@4100 的20个离线候选中按**真实梯度代理**选出，故 room 是开发场景，选参诊断成本未计入训练时间。这个位姿顺序的真实位置梯度前缀范数在4100/5000/10000/30000步分别为0.1734/0.1790/0.1649/0.1686；对应随机排列中位数为0.2409/0.2452/0.2141/0.1723。它不需要在训练时预计算全相机梯度。元数据及原始结果：`fastgs_room_cameras.json`、`fastgs_camera_pose_order_screen.py`、`fastgs_camera_pose_order_result.json`、`fastgs_pose_order_room.json`。

为检验画质，`fastgs_pose_order_training_patch.py` 从作者 `train.py` 生成独立 `train_pose_order.py`。diff 仅添加位姿顺序装载/每轮栈重排，并把取相机改为栈尾弹出；原 `randint` 仍每步调用一次，保持其他 Python 随机数消耗次数。作者 `train.py` 未修改。两臂均使用 SHA256 `d91ba09a5ab040373cc59a93b6864949cb3cc1b5d5b2dea17c79223fef7e927b` 的同一4099步模型与 Adam 检查点、相同模型配置（仅输出目录不同）、原作者全分辨率/损失/增密/优化器。三节点各39张保留视角的 GT PNG 在两臂间逐字节相同。基线是此前一次已保存的作者续训，候选是本次一次续训；因此时间与质量均无多种子方差估计。

## 2026-09-28 源码与先行边界补核

不要将位姿顺序少了 209,341 个终态点归因于“跨相机有符号梯度相消抑制增密”。作者 `scene/gaussian_model.py:528–531` 在**每张图内先取屏幕梯度范数**，然后按 Gaussian 累加非负值；`477–497` 用平均范数门及 `importance_score>5` 选择 clone/split，split 另看 absgrad。因此本报告的有符号 3D xyz 梯度前缀范数代理与实际增密统计不是同一量。相机顺序仍可能通过参数轨迹、可见性、独立评分及剪枝改变点数，但现有终态比较不识别原因。直接降低增密阈值或强加点数下限是未证质量/成本的调参，不构成新机制。

先行边界：[GraB (NeurIPS 2022)](https://papers.nips.cc/paper_files/paper/2022/hash/3acb49252187efa352a1ae0e4b066ced-Abstract-Conference.html) 已提出低额外存储的在线梯度平衡排序；[BOGausS 接受稿](https://hal.science/hal-05444229/document) §III/IV-B 已按相机投影不确定性调整位置/尺度优化步。它们不等于本次 FastGS 固定位姿顺序训练，也不证明同协议三指标胜出，但在线平衡或简单相机几何预调节不能直接宣称新核心。当前没有具体可回本且能追回三指标的不同规则，不启动 Luna 实验。
