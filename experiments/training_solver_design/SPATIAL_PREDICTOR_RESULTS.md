# 空间梯度预测：表示机会与缓存失败必须分开

**2026-09-28 数据来源更正**：本报告的 P11 garden 检查点来自 EPIC-05 旧共享数据的可能性很高；该数据随后被证明包含错误的 1,839,236 点平面灰云。garden 的数值和成本结果只可作该固定状态的算法诊断，不能外推为官方 garden 训练结论；复用前需核对输入哈希。room 独立结果不受此 garden-only 发现影响。见 `P16_GARDEN_POINT_ORDER_AUDIT_20260928.md`。

2026-09-27 数值诊断补记：`garden_transport_mean_diagnostic_v3.json` 在同一
garden 陈旧 16 步状态验证，潜变量的四组预测之和与完整预测相对差约
6.1e-8–8.9e-8；同一完整预测连续投影 VJP 三次逐位一致。但经实际损失合并
后一次反传，rotation 四组均值与原生完整梯度的相对残差仍为 .006481，
普通四组采样为 .000487。说明微小的潜变量分组舍入差在条件不佳的投影反传
后会放大；本诊断尚不能把数值偏差完全归因到单个算子。旧缓存的几何噪声
独立地不通过，因此不推进该方案。v1 诊断因分组索引错误退出，v2/v3 完成；
这三份均保留，不能把 v1 算作成功运行。

## 共享排序的成本门

garden三视角，fine tile16与scaled coarse tile8的counts、ids、flat、offsets
全部逐位相同。fine交集数量分别8,561,680、19,604,552、9,431,594。
这是列表共享的有限范围实现证据，不是任意场景/滤波下的证明。

固定参数下缓存粗层tile16列表，模拟“粗层交集/排序免费”，图像和梯度通过
相同验证门。wall ms/step：

| 视角 | 原生 | 共享+选区 | 粗层排序免费 |
|---|---:|---:|---:|
| 114 | 18.482 | 25.343 | 24.426 |
| 128 | 19.588 | 21.329 | 19.916 |
| 133 | 18.706 | 19.947 | 19.038 |

去掉约0.9–1.4ms仍不足以赢。停止把“仅共享排序”作为下一项训练加速实现。
新tile8光栅内核也许会改变遍历成本，但当前没有相应证据，不为此修改冻结库。

## Adam历史与投影中心分配的负结果

garden三A视角、9×15块、两个四分组随机种子，参数固定，原始完整损失。
中心分配预测器使用保存的Adam一阶矩，经偏差修正并把不可见行归零。
beta=1时原始梯度MSE比为1.009–1.055，所有15个参数组/视角组合都变差；
假想下一步Adam误差也全略增。oracle最佳beta几乎不能提供降噪收益。

即便拿当前完整细图的梯度作不能免费获得的参考，中心分配也常有原始误差
增大；不能由“缓存便宜”推断它有用。room历史探针在GPU3被占用守卫拒绝，
没有运行，不把它计入样本。后来room空间矩探针在干净GPU5正常完成。

## 保留有符号空间矩后的fresh机会

空间矩方案与公式见SPATIAL_PREDICTOR_DESIGN.md。当前完整细图的投影均值/
conic/opacity/颜色梯度生成9节点预测，不是可部署的免费历史。
garden的初始beta=1并不稳定；根据其开发数据选定beta=.5，再独立运行room。
不能把该系数称为在garden之前预注册。

beta=.5时校正原始梯度MSE / 普通块采样MSE：

| 参数 | garden三视角范围 | room三视角范围 |
|---|---:|---:|
| xyz | 0.438–0.507 | 0.299–0.361 |
| SH | 0.438–0.681 | 0.435–0.612 |
| opacity | 0.332–0.576 | 0.370–0.510 |
| scaling | 0.535–0.634 | 0.500–0.711 |
| rotation | 0.607–0.842 | 0.502–0.713 |

garden的.5原始MSE由原始平方和/交叉项精确计算；其已测Adam数据仍是beta=1，
不能当成.5。room实际执行beta=.5，Adam更新误差比0.171–0.463，均下降。
所有fresh样本的图像/原生梯度与矩重建通过；garden无无效可见conic行。
CPU双精度两项测试也通过，但这些只证明表示机会与有限范围代数。

## 固定旧梯度数值的缓存不通过陈旧度门

garden视角114@2000保存一次完整潜变量梯度。随后依原生冻结相机序列，从2000
偏移开始跳过该视角，运行16/64/128步原始dense损失+Adam，固定拓扑，无增密、
剪枝和opacity reset。在各状态评估缓存，不刷新它，也不用评估结果更新模型。
这是同一开发场景的压力测试，不是完整的缓存训练或正式新视角测试。

beta=.5，下面每格为“原始梯度MSE比 / 假想Adam更新误差比”：

| 缓存年龄 | xyz | SH | opacity | scaling | rotation |
|---|---:|---:|---:|---:|---:|
| 0 | .460 / .377 | .591 / .470 | .332 / .270 | .633 / .354 | .842 / .437 |
| 16 | 1.692 / .837 | .780 / .793 | .555 / .765 | 1.405 / .900 | 23.014 / .994 |
| 64 | 2.104 / 1.036 | .850 / .964 | .826 / .915 | 1.979 / 1.296 | 27.355 / 1.421 |
| 128 | 2.255 / 1.099 | .894 / 1.012 | .890 / .943 | 1.680 / 1.388 | 32.453 / 1.516 |

旧梯度数值不能支撑这个长寿命缓存。原始梯度MSE降低也不能保证Adam误差降低：
128步的SH就是一个反例。不要以fresh结果替代这个失败，或直接进入完整训练。

## 屏幕伴随场传递的配对对照也不足以通过

transported_cache_probe.py在同一条新的128步dense轨迹上配对比较固定旧梯度
与固定屏幕二次场的重新积分。CPU独立积分导数检查通过；GPU fresh时两者
一致。field传递在16/64/128步的梯度MSE/Adam误差如下：

| 缓存年龄 | xyz | SH | opacity | scaling | rotation |
|---|---:|---:|---:|---:|---:|
| 16 | 1.203 / .773 | .714 / .789 | .532 / .751 | 1.148 / .803 | 6.985 / .825 |
| 64 | 1.304 / .909 | .756 / .944 | .741 / .886 | 1.535 / .969 | 4.885 / 1.012 |
| 128 | 1.206 / .923 | .855 / .981 | .769 / .894 | 1.746 / .982 | 5.793 / 1.026 |

它缓解部分陈旧度问题，但不是稳定全参数降噪。表格只作原型观察，另有尚未
解释的数值一致性问题：field传递的rotation完整分组均值相对残差在三个陈旧
状态为.03227/.01980/.03134，普通采样为.000221/.000413/.000160，明显更小。
不能把这个差异直接归为通常GPU噪声，也不能因此声称实数无偏证明已在该GPU
实现中可靠保持。现有记录没有mean max-abs项，不能声称已按原来的“relative
或absolute”门判定通过/失败；需要专项诊断。当前不推进完整缓存训练。

此轮所有自有GPU作业均已结束。没有修改冻结库、安装新内核或启动完整训练。
