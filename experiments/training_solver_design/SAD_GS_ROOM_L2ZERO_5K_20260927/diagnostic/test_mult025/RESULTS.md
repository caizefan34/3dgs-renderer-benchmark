# SAD-GS room 5K held-out support counterfactual (2026-09-27)

This is a **post-hoc diagnostic**, not the author's official result or a new method. The independent 5K original-loss checkpoint, all 39 official room test cameras, original 1600x1066 images, author renderer and author `metrics.py` were retained. Only the rasterizer tile-support parameter changed from the author `render.py` default `mult=0.5` to the training setting `mult=0.25`. A separate model directory used a read-only link to the same point cloud and a copied `cfg_args`; the original official renders and metrics were untouched. Luna prepared and completed the render/count pass; after her model-service interruption, root confirmed the process had exited and ran the author metrics command against the isolated directory.

| Same 5K checkpoint, 39 held-out views | PSNR dB ↑ | SSIM ↑ | LPIPS ↓ |
| --- | ---: | ---: | ---: |
| Official author render, `mult=0.5` | 31.218960 | .930894 | .177528 |
| Counterfactual render, `mult=0.25` | 31.303608 | .930532 | .176773 |
| Difference, counterfactual minus official | +.084648 | -.000362 | -.000755 |

On the paired 39 views, 28 improve PSNR, 17 improve SSIM and 29 improve LPIPS; 16 improve all three. The previously identified `00021.png` yellow-veil view improves PSNR by only .097504 dB and worsens LPIPS by .004332. Against the single timed FastGS-Big room reference (32.205460/.930243/.188115), even this counterfactual remains **.901852 dB lower in PSNR**. The 39-view accepted forward Gaussian-pixel pair count at `mult=0.25` is 2,624,076,302; the corresponding `mult=0.5` test-view count was not measured, so no paired test-work ratio or training-wall speedup is claimed. The separate eight-training-view diagnostic measures about 24% more accepted pairs at `mult=0.5` than `0.25`, but that is a different camera sample and forward-count measure.

The source-level difference is that `duplicateToTilesTouched` multiplies the opacity-threshold ellipse's squared radius by `mult`, changing tile support and potentially color. The fixed-checkpoint 39-view result shows this implementation mismatch affects quality, but the isolated render change recovers only about .085 dB of the .987 dB official PSNR deficit in the favorable direction, and its SSIM effect has the opposite sign. It does not justify changing the official evaluation or launching a `mult` sweep/full training arm. Support alignment alone is an existing-system protocol adjustment, not the requested original quality-and-cost mechanism.
