# P17-P0 — Bandwidth-Matched Multirate Gradient Oracle

**Date:** 2026-09-27  
**Status:** frozen preregistration before P17 GPU evidence.

## 0. Research question

P15-P0 established that high optimization utility and high Gaussian–tile cost are structurally aligned. Primitive selection cannot remove the expensive Gaussians without losing too much useful training signal.

P17 asks a different question:

> If an expensive Gaussian has a broad projected footprint, can its parameter update be estimated at a lower image sampling rate while preserving the update that full-resolution training would have produced?

This phase tests that mechanism only.

No new renderer, no training loop, no CUDA production implementation, and no speedup claim are allowed in P17-P0.

---

# 1. Hypothesis

For a projected 2D Gaussian with covariance eigenvalues

\[
\lambda_{\max}\ge \lambda_{\min}>0,
\]

define its minor-axis standard deviation in full-resolution pixels:

\[
\sigma_{\min}=\sqrt{\lambda_{\min}}.
\]

For downsampling factor \(d\in\{1,2,4,8\}\), the same primitive has coarse-grid width approximately:

\[
\sigma_{\min}^{(d)}=\sigma_{\min}/d.
\]

Primary routing rule:

\[
d_i =
\max\left\{
d\in\{1,2,4,8\}:
\sigma_{\min,i}/d \ge \tau
\right\},
\]

with preregistered primary threshold:

\[
\boxed{\tau=2.0\text{ coarse pixels}}
\]

and fallback \(d_i=1\).

Interpretation: a primitive is downsampled only when its narrowest projected axis still spans at least two standard deviations per coarse-pixel scale unit.

Sensitivity-only thresholds:
- \(\tau=1.0\)
- \(\tau=4.0\)

They are reported but **cannot rescue or change the verdict**.

# 4. Camera selection

For each scene, sort training camera IDs deterministically.

Select 12 probe cameras using:

\[
j_k=\left\lfloor (k+0.5)N/12 \right\rfloor,
\qquad k=0,\ldots,11.
\]

Deduplicate only if necessary for a very small camera set; if deduplication occurs, fill using nearest unused sorted IDs.

Select 4 audit cameras from the remaining cameras at sorted quantiles:

\[
0.2,\ 0.4,\ 0.6,\ 0.8.
\]

Freeze all IDs in:

`P17_CAMERA_SET.json`

before any gradient-fidelity result is inspected.

---

# 5. Resolution construction

For each probe camera run:

\[
d\in\{1,2,4,8\}.
\]

The primary datasets have dimensions divisible by 8; nevertheless record exact H×W.

For factor \(d\):

- \(H_d=H/d\)
- \(W_d=W/d\)
- scale \(f_x,f_y,c_x,c_y\) by \(1/d\)
- identical extrinsics
- GT downsampled by deterministic area averaging
- color remains in [0,1]

To preserve the physical meaning of the frozen 2D covariance stabilizer:

\[
\epsilon_{2D}^{(d)}
=
0.3/d^2.
\]

Do not tune eps2d after seeing gradients.

The same frozen fused loss is evaluated at the coarse resolution.

---

# 6. Renderer-state discipline

Every independent render/backward starts from a fresh dynamic-scene state.

Use the P13-Y lesson:

- do **not** call `mark_dirty()` to separate independent no-grad/backward renders while a backward may be pending;
- reset the dynamic scene before each oracle render;
- verify d=1 reproduces the ordinary frozen trainer frame/gradient.

A d=1 parity failure invalidates the unit.

---

# 7. Full-resolution reference

For each probe camera at d=1 save:

- full fused loss
- full RGB render hash
- exact tile/intersection metadata
- projected covariance / conic information
- per-Gaussian exact intersection count \(c_i^{(1)}\)
- \(\sigma_{\min,i}\), \(\sigma_{\max,i}\)
- raw gradients for:
  - means
  - scales
  - quats
  - opacity
  - SH0
  - SH-rest

Use the exact raw parameterization used by the optimizer.

No transformed-space gradient may replace the raw optimizer gradient in the primary gate.

---

# 8. Coarse-gradient probes

For d=2,4,8 compute gradients from the coarse loss.

For each Gaussian retain:

\[
g_{i,p}^{(d)}
\]

for every raw parameter group \(p\).

Also record exact coarse intersection counts:

\[
c_i^{(d)}.
\]

Do not approximate coarse cost by \(c_i^{(1)}/d^2\).

---

# 9. Primary multirate assignment

For \(\tau=2.0\), assign each visible Gaussian independently for each camera to:

\[
d_i\in\{1,2,4,8\}.
\]

Create the hybrid gradient:

\[
g_{i,p}^{hyb}=g_{i,p}^{(d_i)}.
\]

Thus broad Gaussians use coarse gradients and narrow Gaussians retain full-resolution gradients.

This is an **oracle assembly**. P17-P0 does not claim that the final renderer can yet obtain this hybrid gradient at the measured oracle cost.

---

# 10. Gradient-fidelity metrics

For each camera and each raw parameter group, concatenate all Gaussian entries assigned to d>1 and compute:

### Cosine

\[
\cos_p =
\frac{
g_{p}^{full}\cdot g_{p}^{hyb}
}{
\|g_{p}^{full}\|\|g_{p}^{hyb}\|+\epsilon
}.
\]

### Relative L2

\[
E_{p,L2}=
\frac{
\|g_p^{hyb}-g_p^{full}\|
}{
\|g_p^{full}\|+\epsilon
}.
\]

### Top-gradient sign agreement

On the top 10% absolute full-gradient coordinates:

\[
A_{sign,p}
=
\frac{
\#\{\operatorname{sign}(g^{hyb})=\operatorname{sign}(g^{full})\}
}{
K
}.
\]

Relative-L2 is diagnostic because Adam is partly scale-normalizing. The actual decision therefore also includes the optimizer one-step test below.

---

# 11. Hybrid one-step Adam oracle

For every probe camera:

1. clone the exact 16K parameters and optimizer state;
2. create a dense-reference clone;
3. apply one ordinary full-resolution C0 Adam step to the dense clone;
4. apply one step to the hybrid clone using \(g^{hyb}\);
5. preserve all normal P12 optimizer semantics;
6. no densification / topology event.

Evaluate exact full-resolution fused loss after each step on:

- the training probe camera;
- the same 4 fixed audit cameras.

Define:

\[
G_{dense}
=
L_{before}-L_{after,dense}
\]

\[
G_{hyb}
=
L_{before}-L_{after,hyb}
\]

\[
R_{step}
=
G_{hyb}/\max(G_{dense},10^{-12}).
\]

Audit penalty:

\[
P_{audit}
=
\frac{
L_{audit,after,hyb}-L_{audit,after,dense}
}{
L_{audit,before}
}.
\]

If \(G_{dense}\le0\), mark the probe `STEP_NONIMPROVING_REFERENCE`; retain it but exclude R_step from the median and report the count.

---

# 12. Work oracle

For each camera, using the actual intersection counts measured at each assigned resolution:

\[
C_{oracle}
=
\frac{
\sum_i c_i^{(d_i)}
}{
\sum_i c_i^{(1)}
}.
\]

Also report the fraction of original full-resolution interaction work belonging to Gaussians assigned to d>=2, d>=4, and d=8.

Important:

\[
C_{oracle}
\]

is an **interaction-work lower-bound oracle**, not an implementable E2E runtime estimate.

It ignores:
- multi-pass launch floors,
- cross-scale compositing,
- full-resolution context requirements,
- loss cost,
- optimizer cost,
- merge/upsampling cost.

No speedup claim can be based on \(1/C_{oracle}\).

---

# 13. Stage-A candidate gates — primary tau=2 only

For **each** of room and bicycle:

### Work opportunity

- median \(C_{oracle}\le0.30\)
- 75th percentile \(C_{oracle}\le0.35\)

### Geometry gradient fidelity

For the d>1 population across 12 probe cameras:

- median means cosine >= 0.995
- 10th-percentile means cosine >= 0.990
- median scale cosine >= 0.990
- median quaternion cosine >= 0.990

### Appearance / opacity fidelity

- median opacity cosine >= 0.995
- median SH0 cosine >= 0.990

SH-rest is reported; it is not a Stage-A hard gate because many states/large Gaussians can have near-zero high-order SH gradient.

### Update fidelity

Across improving-reference probes:

- median \(R_{step}\in[0.95,1.05]\)
- at least 10/12 probes have \(R_{step}\in[0.90,1.10]\)

### Generalization

- median \(P_{audit}\le0.002\)
- no more than 1/12 probe steps has \(P_{audit}>0.01\)

If both scenes satisfy all candidate gates:

`P17_P0_STAGE_A_STRONG`

and run garden.

---

# 14. Stage-A hard DROP

Emit:

`P17_P0_HARD_DROP`

and STOP before garden if **either scene** has any of:

- median \(C_{oracle}>0.50\), or
- median means cosine < 0.980, or
- median opacity cosine < 0.980, or
- median \(R_{step}<0.80\), or
- at least 4/12 probes have \(P_{audit}>0.01\).

Sensitivity thresholds tau=1/4 cannot rescue this decision.

---

# 15. HOLD region

If Stage A is neither strong nor hard-drop:

`P17_P0_HOLD_NO_STRONG_ORACLE`

Stop P17 before implementation.

Do not tune tau, loss, eps2d, camera set, or resolution levels to rescue it.

---

# 16. Garden validation

Only after `P17_P0_STAGE_A_STRONG`.

Garden must satisfy the same primary gates.

If yes:

`P17_P0_GO_MULTIRATE_REALIZABILITY`

If no:

`P17_P0_HOLD_CROSS_SCENE`

Even GO means only:

> low-resolution parameter gradients appear information-preserving enough to justify studying a realizable multirate renderer.

It does **not** mean:
- >3x training speedup,
- a production design exists,
- novelty is established.

---

# 17. Required next-phase question after GO

P17-P1 must solve the issue P0 deliberately ignores:

> How can multiple Gaussian scale groups be rendered/optimized without paying a full-resolution context pass that destroys the theoretical savings?

P1 must include:
- cross-scale alpha/depth compositing semantics,
- measured launch/fixed floors,
- exact/approximate quality classification,
- E2E Amdahl model on the winner of P16-RB.

No CUDA production kernel before a P1 conservative oracle predicts >=4x E2E headroom on the P16 strong baseline.
