# BWD-ARITH1-RECOMPUTE-GAUSSIAN
## Exact Forward-to-Backward Gaussian Response Reuse on MX A100

# 1. Mission

Answer exactly:

> Is storing the exact forward Gaussian response and loading it during backward cheaper than recomputing the Gaussian response in `blend_backward_cu`, after accounting for real memory traffic, buffer size, production integration, and full-iteration timing?

This is an exact systems optimization.

No Gaussian approximation is authorized.

No linearized Gaussian.

No reduced precision unless separately diagnostic and not used for the primary candidate.

No change to gradient semantics.

---

# 2. Mathematical target

For one Gaussian-pixel interaction, forward evaluates a Gaussian response of the form:

\[
G
=
\exp\left(
-\frac12
\left[
a\Delta x^2
+
2b\Delta x\Delta y
+
c\Delta y^2
\right]
\right).
\]

Opacity contribution is based on:

\[
\alpha=oG.
\]

Backward later requires the same \(G\) in derivatives for opacity, conic and mean.

The candidate optimization is:

### Baseline

Forward:

\[
G_f=\exp(-Q/2)
\]

Backward:

\[
G_b=\exp(-Q/2)
\]

so Gaussian response is recomputed.

### Candidate

Forward:

\[
G_f=\exp(-Q/2)
\]

store exact \(G_f\).

Backward:

\[
G_b\leftarrow G_f
\]

load the previously computed value.

Required mathematical contract:

\[
\boxed{
G_b = G_f
}
\]

up to the exact storage representation used by the primary candidate.

Primary candidate storage must be FP32.

# 11. Diagnostic variants

Implement all variants in the same source/binary where practical, selected by runtime flag, to minimize resource confounds.

## R0 — Production recompute

Original production behavior.

Backward recomputes:

\[
G=\exp(-Q/2).
\]

This is the reference.

---

## R1 — Exact forward cache

Forward stores exact FP32 Gaussian response for every interaction that backward would otherwise recompute.

Backward loads:

\[
G_{\mathrm{cached}}
\]

and uses it in the original gradient equations.

No approximation.

This is the actual candidate.

---

## R2 — Cache write-only diagnostic

Forward writes the same cache as R1.

Backward still recomputes \(G\).

Purpose:

measure forward cache-production overhead separately.

---

## R3 — Load-only synthetic diagnostic

Where scientifically implementable without changing traversal semantics:

pre-fill a cache with correct values outside the timed interval and run backward using loads.

Purpose:

separate backward load cost from forward write cost.

This is diagnostic only.

---

# 12. Exact cache indexing

The cache index must correspond exactly to the interaction whose \(G\) is consumed in backward.

No ambiguous reconstruction.

Document mapping:

\[
(\text{tile},\text{bucket},\text{primitive},\text{pixel})
\rightarrow
\text{cache index}.
\]

Prefer reuse of existing traversal/order metadata.

Do not introduce a global sort merely to index the cache.

If indexing itself requires expensive new metadata, measure it.

---

# 13. Early termination / skip semantics

Only store \(G\) values that correspond to interactions actually needed by backward.

Correctly handle:

- invalid primitive
- invalid pixel
- alpha threshold
- early termination
- `last_contributor`
- image boundary
- proper antialiasing mode

Do not create a dense cache for interactions the baseline never processes unless used solely as an explicitly labeled upper-bound diagnostic.

\[
S_B=
\frac{T_B^{R0}}

\[

\le

}

\[

# 21. Net renderer gate

\[
S_R=

# 36. DROP_REUSE_TRAFFIC_OVERHEAD

Use if:

\[

\]

# 39. No rescue rule

STOP.

Do NOT automatically try:

- FP16 cache
- BF16 cache
- quantization
- selective cache
- compressed cache
- hot-only cache
- altered bucket size
- approximate Gaussian
- changed alpha threshold

BWD-ARITH0 proved:

\[
\text{backward Gaussian recomputation has measurable arithmetic cost}.
\]

BWD-ARITH1 must answer the harder production question:

\[
\boxed{
